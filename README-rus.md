# Как установить CometScout на виртуальную машину с Debian

> До октября 2026 года CometScout назывался jobpilot. Установка в `~/jobpilot` продолжает работать; `deploy/install.sh` найдёт её, не тронет и подскажет, как её перенести.

CometScout каждый вечер собирает вакансии, оценивает каждую по вашему профилю, выбирает две лучшие и готовит под них резюме и черновики ответов для формы отклика. Все модельные шаги идут через вашу подписку Claude или ChatGPT, отдельный API-ключ не нужен.

## Что понадобится

- Виртуальная машина с Debian 12 или 13: от 2 ГБ оперативной памяти и 10 ГБ диска.
- Обычный пользователь с правами sudo. Под root ставить не нужно.
- Подписка Claude (Pro или Max) или ChatGPT (Plus или Pro).
- По желанию: бот в Telegram для ежедневной доставки и почта Gmail, если у вас настроены рассылки вакансий LinkedIn.

## 1. Подготовка машины

Если sudo ещё нет, зайдите под root и выполните (вместо `ИМЯ` ваш пользователь):

```bash
apt-get update && apt-get install -y sudo && usermod -aG sudo ИМЯ
```

Затем перезайдите под своим пользователем и поставьте git и Node.js 20 или новее.

**Debian 13:** Node 20 есть в стандартных репозиториях.

```bash
sudo apt-get update && sudo apt-get install -y git curl nodejs npm
```

**Debian 12:** там Node 18, он не подойдёт. Нужная версия ставится из NodeSource.

```bash
sudo apt-get update && sudo apt-get install -y git curl
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
```

Проверка: команда `node -v` должна показать v20 или выше.

## 2. Claude Code или Codex

Поставьте один из двух.

**Claude Code:**

```bash
curl -fsSL https://claude.ai/install.sh | bash
source ~/.profile
claude
```

Установщик кладёт `claude` в `~/.local/bin`. Debian добавляет эту папку в PATH при входе в систему, поэтому сразу после установки нужна строка `source ~/.profile` (или просто перезайдите по SSH).

При первом запуске Claude Code покажет ссылку. Откройте её в браузере на своём компьютере, войдите и вставьте в терминал код, который покажет сайт. После входа выйдите командой `/exit`.

**Codex:**

```bash
sudo npm install -g @openai/codex
codex login
```

Если на машине нет браузера, следуйте подсказкам `codex login` для входа без браузера.

## 3. Установка CometScout

```bash
cd ~
git clone https://github.com/Dreamkeeper/cometscout.git
cd cometscout
bash deploy/install.sh
```

Установщик один раз попросит пароль для sudo и сделает следующее:

- поставит Python, LibreOffice для PDF и шрифты;
- создаст `settings.json` и `.env`, закрытый от чужих глаз;
- настроит ежедневный запуск в 18:00. Пока нет вашего профиля (папки `profile/`), вечерний запуск ничего не делает. Дни, время и часовой пояс потом задаются в `settings.json` (`"schedule": { "days": [1, 2, 3, 4, 5], "time": "18:00" }`, `timezone`), после чего нужно выполнить `node cli.mjs timer`; их можно менять и в рабочем окне, и в Telegram-боте;
- в конце запустит проверку `node cli.mjs doctor`.

Проверка выводит список: `ok` значит готово, `TODO` значит, что ещё сделать. Сразу после установки пункты про профиль и настройки будут в `TODO`, так и должно быть.

## 4. Проверка на примере

Пока своего профиля нет, CometScout работает на вымышленном примере (Alex Rivera):

```bash
node cli.mjs sources
node cli.mjs decode --no-telegram
node cli.mjs pack --no-telegram
```

Результаты появятся в `data/`: разборы вакансий, выбор дня и пакеты с резюме в PDF.

## 5. Настройка под себя

Откройте папку в Claude Code или Codex:

```bash
cd ~/cometscout && claude
```

(или `codex` вместо `claude`) и напишите: **«set me up»** или **«настрой меня»**.

Агент проведёт вас по шагам и будет задавать по одному вопросу:

1. **Профиль:** кто вы, какие роли ищете, где можете работать, что вам точно не подходит, и чего про вас нельзя писать ни при каких условиях.
2. **Библиотека резюме:** агент разберёт ваше резюме на пункты, и вы подтвердите каждую строку. Резюме под вакансии собираются только из этих пунктов, модель ничего не придумывает.
3. **Правила фактов:** проверка, которая ловит преувеличения.
4. **Ваш стиль:** по желанию. Пришлите два-три текста, написанных вами самими, чтобы ответы в формах звучали как вы.
5. **Первый источник:** проще всего начать с публичных страниц вакансий компаний на Greenhouse, Ashby и Lever. Назовите 5–10 компаний, агент сам найдёт их страницы.
6. **Первый результат:** настоящая вакансия, разобранная по вашему профилю, и резюме под неё в том же сеансе.

## 6. Доставка в Telegram

1. Создайте бота у @BotFather и скопируйте токен.
2. Узнайте свой chat id, например у @userinfobot.
3. Откройте файл `.env` (`nano ~/cometscout/.env`) и добавьте две строки:

```
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TELEGRAM_CHAT_ID=ваш_chat_id
```

4. В `settings.json` включите `"delivery": { "telegram": { "enabled": true } }`, или попросите агента.
5. Чтобы подписи в сообщениях (дайджест, выбор на сегодня, пакеты для отклика) были на русском, добавьте в `settings.json` строку `"locale": "ru"`. Текст, который пишет модель, не переводится.

Если запуск по таймеру упадёт, бот пришлёт сообщение об ошибке (после `node cli.mjs timer`).

После включения Telegram выполните `node cli.mjs timer` ещё раз: он установит и службу бота. Бот отвечает только в вашем чате:

- `/schedule`: дни сводки, время и подготовка к собеседованию, с кнопками, чтобы включать и выключать дни и задавать дни подготовки (от 0 до 3);
- `/time 19:30`: перенести вечерний запуск;
- `/interview Компания 2026-10-07 14:00`: записать назначенное собеседование (название из нескольких слов возьмите в кавычки);
- `/help`: список команд.

В выключенные дни запуск по-прежнему собирает и разбирает вакансии, но ничего не присылает; первая сводка после них говорит, что пришло за это время.

**Токены вписывайте в файл сами и никогда не вставляйте их в чат с агентом.**

## 7. По желанию: рассылки LinkedIn через Gmail

Этот шаг для тех, кому LinkedIn уже присылает письма с подборками вакансий.

1. В Google Cloud Console создайте проект, включите Gmail API, настройте экран согласия (External, себя добавьте в тестовые пользователи) и создайте OAuth-клиент типа «Desktop app». Агент может провести по этим шагам.
2. Впишите в `.env` строки `GMAIL_CLIENT_ID=...` и `GMAIL_CLIENT_SECRET=...`.
3. На **своём компьютере** откройте туннель к машине:

```bash
ssh -L 8765:127.0.0.1:8765 ИМЯ@адрес_машины
```

4. В этом же SSH-сеансе запустите:

```bash
cd ~/cometscout && node tools/gmail-auth.mjs
```

5. Откройте ссылку, которую выведет скрипт, в браузере на своём компьютере, войдите и разрешите доступ только на чтение. Ключ доступа сам запишется в `.env` и нигде не будет показан.
6. Включите источник `linkedin_alerts` в `settings.json` и проверьте его:

```bash
node sources/linkedin-alerts.mjs --dry-run --max-fetch 3
```

Источник RealtimeJobs включается так же: токен `RTJ_API_TOKEN=...` в `.env` и `"rtj": { "enabled": true }` в настройках.

Hirify (вакансии на удалёнку и с релокацией) читается через вашу сессию на сайте: скопируйте из браузера значение заголовка `Cookie` в строку `HIRIFY_COOKIE="..."` в `.env` (сами, не в чат), добавьте свои сохранённые фильтры в блок `"hirify"` в `settings.json` и проверьте `node sources/hirify.mjs --dry-run`. Подробности, в том числе что делать, когда сессия истекла: раздел [Hirify](README.md#hirify) в README.

Если у вас уже работает [career-ops](https://github.com/career-ops-hq/career-ops), CometScout может забирать его находки: впишите путь к папке career-ops в `sources.career_ops.path` и включите источник. CometScout только читает `data/pipeline.md` и `data/scan-history.tsv` и ничего не пишет в папку career-ops. Подробности в разделе «career-ops» файла `README.md`.

## 8. Каждый день

- Вечером в Telegram приходят до двух лучших вакансий дня, к каждой пакет: резюме в PDF, сопроводительное письмо, если форма его просит, и черновики ответов.
- Откликнулись: `node cli.mjs applied Компания`, чтобы вакансия больше не предлагалась.
- Появились новости: `node cli.mjs status Компания interview` (или `offer`, `rejected`, `skipped`).
- Приняли оффер и работаете, но продолжаете искать: `node cli.mjs status Компания accepted`. Такая работа больше не считается открытым процессом, и письма её статус не меняют.
- Назначили собеседование: `node cli.mjs interview Компания 2026-10-07 14:00` (или `/interview` в боте, или «Записать собеседование» в рабочем окне). За 2 дня до него сводка начинается с собеседования и шага подготовки и предлагает не больше одной новой вакансии, только сильную и свежую; остальные ждут до окончания собеседования. `"picks": { "prep": { "days_before": 0 } }` выключает это.
- Все отклики: `node cli.mjs list`.
- Очистить данные после пробы на примере: `node cli.mjs reset --yes`.

## 9. Выгрузка данных и резервные копии

- Каждый вечер после запуска CometScout сам делает резервную копию в папку `backups/` (ZIP-файл). Старые копии удаляются сами: остаются копии за последние 7 дней, 4 недели и 6 месяцев. Выключить: `"backup": { "nightly": false }` в `settings.json`.
- Сделать копию сейчас: `node cli.mjs backup`. Список копий: `node cli.mjs backups`.
- Вернуть данные из копии: `node cli.mjs restore <имя файла> --dry-run` покажет, что изменится; та же команда без `--dry-run` восстановит данные. Перед этим CometScout сам сохранит текущее состояние.
- Выгрузить всё в один ZIP (его можно открыть двойным щелчком): `node cli.mjs export`. Только отклики в таблицу для Excel: `node cli.mjs export --csv отклики.csv`.
- Перенести на новый сервер: `node cli.mjs export --out cometscout.zip` на старом, скопировать файл, `node cli.mjs import --from cometscout.zip` на новом.
- Расшифровки записей (`data/transcripts`) входят в выгрузку и копии, сами аудиозаписи (`data/audio`) нет.
- Токены из `.env` в выгрузку и копии не попадают. Их переносят отдельно, в зашифрованном файле: `node cli.mjs export-secrets --out secrets.enc` и `node cli.mjs import-secrets --from secrets.enc` (пароль спросят).
- Если будете сами перепаковывать выгрузку на Windows, берите 7-Zip или PowerShell (`Compress-Archive`). Проводник и `tar.exe` пишут имена в старой кодировке; если такой архив потом загружается на сервер, укажите там в `settings.json` `"backup": { "zip_codepage": 866 }`.

Подробности: раздел [Export, import and backups](README.md#export-import-and-backups) в README.

## 10. По желанию: тренер для собеседований

CometScout умеет поставить рядом с собой [Interview Coach](https://github.com/noamseg/interview-coach-skill), открытый навык для Claude Code от Noam Segal (лицензия MIT): подготовка к компании, тренировка ответов, разбор записи собеседования, переговоры об оффере. Это отдельный проект, он ставится из своего репозитория. Установить или обновить: `bash deploy/modules/coach.sh`. Передать ему ваш профиль, резюме, стиль письма и отклики: `node cli.mjs coach-handoff` (файл появится в папке тренера, в `materials/cometscout-handoff.md`; токены, тексты вакансий и пакеты в него не попадают). Когда в настройках `modules.coach.enabled` равно `true`, вечерний запуск обновляет этот файл сам. Затем `cd ../interview-coach && claude`, скажите `kickoff` и дайте ему файл `materials/cometscout-handoff.md`. Подробности: раздел [Interview coach](README.md#interview-coach-optional) в README.

## 11. По желанию: расшифровка записей собеседований

CometScout умеет превращать запись собеседования в текст прямо на сервере, чтобы тренер мог её разобрать (`analyze`). Запись никуда не уходит; модель (около 1,5 ГБ для `medium` по умолчанию) скачивается один раз при первой расшифровке. Говорящие пока не разделяются.

```bash
bash deploy/modules/transcribe.sh                   # нужны Python 3.10-3.14 и python3-venv: sudo apt-get install -y python3 python3-venv
node cli.mjs transcribe --bench sample.m4a --models small,large-v3-turbo   # какая модель успевает на этой машине
```

Затем в `settings.json` поставьте `modules.transcribe.enabled` в `true` (и `model`, которую подсказал замер) и выполните `node cli.mjs timer`. Записи кладите в `data/audio/inbox` (scp или Syncthing), загружайте кнопкой «Расшифровать» в рабочем окне или присылайте боту (до 20 МБ). Расшифровки появятся в `data/transcripts/`, а при включённом тренере ещё и в его `materials/transcripts/`. Если включён Telegram, бот пришлёт сообщение «Расшифровка готова» с файлом `transcript.md` (выключить файл: `modules.transcribe.telegram_attach` в `false`; файл больше 50 МБ бот не отправит, придёт только сообщение). Расшифровки попадают в выгрузку и резервные копии, аудио нет. Подробности: раздел [Transcription](README.md#transcription-optional) в README.

**Русские записи.** Whisper в длинном русском разговоре иногда переворачивает смысл, придумывает слова и теряет пунктуацию. GigaAM v3 от Сбера (лицензия MIT) заметно точнее на русском и в несколько раз быстрее на процессоре, но коверкает английские слова: «роадмап» вместо roadmap. Поэтому русские записи расшифровывают оба движка: основа текста и пунктуация от GigaAM, а слово Whisper ставится только там, где он в тот же момент услышал латинский термин, аббревиатуру или число. Русское слово на другое русское не меняется никогда: такие расхождения попадают в список «Проверьте эти слова» в конце `transcript.md`, а все внесённые правки в список «Внесённые правки».

```bash
bash deploy/modules/transcribe.sh --with-gigaam    # PyTorch только для процессора (около 115-190 МБ загрузки) и GigaAM; нужен Python 3.10-3.14
```

Модель GigaAM (около 0,45 ГБ) скачается с сервера Сбера при первой русской записи. Без этого дополнения русские записи расшифровывает один Whisper, и в расшифровке это сказано. Какой движок для какого языка, задаёт `modules.transcribe.engines` (по умолчанию `{ "ru": "gigaam+whisper", "default": "whisper" }`); язык Whisper определяет по первым 30 секундам речи (тишину в начале пропускает) и в том же процессе расшифровывает запись. Если он не уверен (меньше `language_floor`, по умолчанию 0.6), решает `language_fallback`: `"auto"` (по умолчанию) значит расшифровать одним Whisper, а код языка вроде `"ru"` значит считать запись на этом языке; в расшифровке это сказано.

Перед каждой расшифровкой CometScout собирает словарь ваших слов: компании из откликов и вакансий за 90 дней, названия продуктов и технологий из резюме и `profile/profile.md`. Свои термины добавьте в `profile/glossary.txt`, по одному в строке; как термин произносят, можно указать так: `KPI = кейпиай`. Whisper получает первые 50 терминов как подсказку, а слова GigaAM, похожие по звучанию на любой термин словаря, получают его написание. Русские слова из свободного текста часто стоят в падеже («в Лунабанке»): такая форма заменяется начальной, если она тоже есть в тексте, а иначе остаётся только подсказкой для Whisper; термин никогда не меняет у слова одно окончание. Термины из `glossary.txt` и настроек используются как написаны. Словарь не покидает сервер; использованный список лежит рядом с расшифровкой в `glossary-used.txt`. Сравнить движки на своей записи: `node cli.mjs transcribe --bench запись.m4a --engines whisper,gigaam,gigaam+whisper --reference текст.txt`.

**Кто говорит.** С дополнением для говорящих каждая строка расшифровки подписана говорящим, а ваши реплики помечены «Я», и тренер сразу оценивает ваши ответы. Модели (около 35 МБ) скачиваются с GitHub-релизов k2-fsa с проверкой sha256, без аккаунта Hugging Face.

```bash
bash deploy/modules/transcribe.sh --with-speakers   # sherpa-onnx и две небольшие модели; нужен Python 3.10-3.14
```

Затем поставьте `modules.transcribe.speakers.enabled` в `true` и запишите 20-60 секунд своей речи без других голосов (на любом языке) в `profile/my-voice.wav`: говорящий с самым похожим голосом получит метку «Я», если сходство выше порога. Образец не покидает сервер. Для разговора один на один укажите `"num_speakers": 2`. Остальных говорящих можно назвать: `node cli.mjs transcribe --rename <папка расшифровки> "Говорящий 2=Интервьюер"` или в окне «Расшифровать» рабочего окна; md и srt перепишутся. Похожие голоса, больше четырёх говорящих и долгая одновременная речь даются хуже; проверьте имена перед тем, как отдать расшифровку тренеру. Подробности и замеры: раздел [Speakers](README.md#speakers-optional) в README.

## 12. По желанию: CometScout из AI-клиента (MCP)

`node cli.mjs mcp` это MCP-сервер: Claude Code, Claude Desktop или Codex на вашем компьютере видят состояние CometScout, объясняют, чего не хватает, записывают статусы откликов и меняют настройки с теми же проверками, что и `doctor`. Клиент запускает сервер через SSH, отдельный порт не нужен. Нужен вход по ключу без пароля и `cometscout` в PATH на сервере (один раз `npm link` в папке CometScout), иначе укажите полный путь: `ssh <host> node /home/you/cometscout/cli.mjs mcp`.

```bash
claude mcp add cometscout -- ssh <host> cometscout mcp                       # Claude Code: чтение и статусы
claude mcp add cometscout-admin -- ssh <host> cometscout mcp --scope admin   # плюс настройки и секреты
```

Уровни доступа: `read` (только чтение), `operate` (по умолчанию: плюс статусы, собеседования и добавление вакансии), `admin` (плюс `settings_set` и `secrets_form`); `mcp.scope` в `settings.json` может только понизить уровень. Секреты через чат не проходят: `secrets_form` выдаёт одноразовую ссылку на страницу рабочего окна (через туннель `ssh -L 8787:127.0.0.1:8787 <host>`), значение вводится в браузере и сразу записывается в `.env`; ссылка работает один раз и 15 минут. Ссылка записывает только секреты, которые CometScout читает сам (`RTJ_API_TOKEN`, `HIRIFY_COOKIE`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`). Ключи `*_env` и `workspace.url` через MCP не меняются, только вручную по SSH. Переменные вроде `NODE_OPTIONS`, `PATH`, прокси и `COMETSCOUT_*` из `.env` не загружаются, `doctor` их показывает. Каждый вызов, который что-то меняет, записывается в `data/state/mcp-log.jsonl` без секретов. Настройки для Claude Desktop и Codex: раздел [Use it from an AI client (MCP)](README.md#use-it-from-an-ai-client-mcp) в README.

## Если что-то не работает

- `node cli.mjs doctor` показывает, чего не хватает, и как это исправить.
- Лог вечернего запуска: `journalctl --user -u cometscout -n 100`.
- Когда следующий запуск: `systemctl --user list-timers cometscout.timer`.
- Запустить весь конвейер вручную: `node cli.mjs run`.
